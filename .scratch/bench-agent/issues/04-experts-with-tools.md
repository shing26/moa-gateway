# 04 — 专家接工具循环

**What to build:** 协作链路里的 coder / general / review 目前只吐字符串，不会读写文件、不会跑测试——没有行动能力的执行体撑不起 L2/L3。给专家池接上工具循环，让专家能真正改代码。这既是为 L2/L3 铺路，也是这个实验要讲的那一课：agent 不只是提示词，还得有行动能力。收工时一个专家能独立把某条失败测试从红改到绿。

**Blocked by:** 02 — arm 缝

**Status:** done

- [x] 专家使用与 L0 同一套工具集与同一个工具契约，不另起一套
- [x] 专家的行动轨迹与用量进入同一个账本（可归因到具体专家）
- [x] 离线用例：scripted 专家写真修复 → 验证通过
- [x] 工具被拒 / 执行失败降级成观察，不中断专家循环
- [x] 先查清现有 task agent 是否已有可复用的工具循环，有则复用而不是再写一套

**落地：** `bench/agent/expert.py`（专家池接在 §5.0 的 `LLMBackedAgent` 上，`app/`
零改动——落点取舍见 ADR-023 §5.1 补记与设计 §13.2）。归因目前到"每个专家的
`AgentRun`"这一层；把 N 个专家的 run 合进一份账本时的逐专家用量拆分是 **06** 的
活（并发下账本不串），本票不预支。

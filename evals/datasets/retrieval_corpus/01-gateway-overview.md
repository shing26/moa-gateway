# moa-gateway 是什么

moa-gateway 是一个 LLM 治理层，不是一个全能 agent。它的价值主张是：让不受控的
模型输出变得可审批、可审计、可回归。这三点分别对应守卫与人工审批、审计日志、
以及评测门禁。

## 请求链路

请求链路是：飞书或 Webhook 进入，经过鉴权与限流，进入自研状态机编排，然后做
意图路由，再交给注册表里的 Agent 执行，最后经过守卫策略与人工审批，送达用户。
这条链路上的每一个环节都有审计留痕，可以按 trace_id 串起来复盘。

## 运行时依赖

项目默认运行时不依赖 LangChain 或 LangGraph。LLM 调用层使用 LiteLLM 支持多
Provider、fallback 与成本统计。另提供可选的 LangGraph 第二引擎用于框架等价性
验证，默认关闭。切换引擎只需要改一个环境变量，不需要改代码。

## 治理对象

治理的对象是模型输出，不是操作动作。这一点决定了它的边界：它不做操作审批，
不做工单流转，只对模型说出的话负责。被拦截或需要审批的输出不会进入长期记忆，
只有成功交付的输出才会被记住。

## 定位边界

项目明确不做平台级替换，不做跨云多租户，不做大规模重写。它吸收业界范式但只
修正接线，不引入运行时平台。被问支持哪些渠道时，回答是渠道是配置级工作，
框架是可选对照，重点做的是把输出关进合规笼子。

## 成本与可观测性

每次 LLM 调用都记录 model_used、cost_usd、llm_latency_ms 与 fallback_used，
随审计日志落盘。意图路由的三级降级本身也是省钱手段：正则命中的请求不调
任何 LLM，实测 92% 由正则直接命中。OTel trace 贯穿请求链路，审计可以按
trace_id 关联，dashboard 展示成本与延迟的趋势。

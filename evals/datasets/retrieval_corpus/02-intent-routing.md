# 意图路由的三级降级

意图路由决定一个请求该交给哪个 Agent。它有三层，按成本从低到高依次升级，
任何一层给出判定就立即返回，不再往下走。

## 第一层：正则表

第一层是正则表。命中就直接返回，不调任何 LLM，毫秒级返回。实测 50 条用例里
有 46 条由正则直接命中，占 92%。正则表覆盖 coding、debug、search、translate、
summarize、analyze、greeting、control、task 等意图。

## 第二层：微模型

第二层是微模型。正则未命中时才升级到微模型，用一个更便宜的小模型做分类。
微模型有独立的超时配置，超时或报错就继续往下走，不会阻塞请求。

## 第三层：路由 LLM

第三层是路由 LLM。微模型也不可用时才用主模型做路由分类。主模型失败时路由
返回默认意图 assistant，并在审计里记录 route_fallback 为 none，表示这一层
没有给出判定。这个字段是可见性的关键：没有它，路由一直在超时这件事在数据里
完全看不见。

## 意图与 Agent 的对齐

意图标签与 Agent 注册键之间有一张同构对齐表，把 coding 映射到 coder，把
review 映射到 review，未知意图一律回退 general。这张表在启动期自检，映射值
必须是合法注册键，否则立即失败，避免键不匹配再次发生。

## 路由超时与可见性

路由对每个请求返回 intent 与 level，level 为 none 表示微模型或路由 LLM 那一层
没给出判定，intent 因此是默认值。此时"稳定"是"一致地降级"，不是"判断稳定"。
报告必须把降级次数放在稳定率旁边，否则稳定率 1.0 单独拿出来看毫无意义。
冷启动首次调用可能超过超时阈值，超时取消后模型热不起来，结果是所有非正则
输入静默降级成默认意图，而报告里一切正常。

# 守卫与人工审批

守卫对一次模型输出做三态裁决：放行、拦截、转人工。中间那一档是关键，因为它
把"不该直接做"和"不能做"分开了。

## 策略引擎

策略引擎覆盖内网 IP、密钥与 Token、价格承诺。输出命中 deny 直接拦截，命中
review 进入人工审批。静态评估器同样接入刹车：AST 危险类问题直接拦为 deny，
不可审批；空输出、超长、非法 JSON 等质量问题进人工 review。

## 人工审批闭环

人工审批通过飞书卡片闭环。审批卡片带 trace_id，点击通过则送达，点击拒绝则
丢弃。审批人白名单非空即强制：点击者不在名单里返回 403，且不消耗挂起记录，
因为消耗了就代表这次审批没了，别人再也批不了。

## 红队实测

红队实测 200 条对抗用例，期望拦截 120 条全部命中，漏网 0，误拦截 0，召回率
与精确率都是 100%。用例与策略正则同源，所以 100% 是防漂移不变量，不是泛化
能力证据。

## 失败升级

执行期失败带归因重试一次，再失败自动升级人工。重试预算由状态机表结构决定，
恒为 1，不是配置项。升级复用同一套审批闭环，hitl_kind 区分来源是策略命中
还是失败升级。

## 审批卡片字段

审批卡片必须带 trace_id，否则点击后无法按 trace 回流评测。卡片上展示 agent_name、
intent、guard_reason 与 policy_hits，让审批人知道自己在批什么。同一策略可能因
多条正则各命中一次，policy_ids 会重复，给用户看的文案按策略去重并带上人话名，
避免审批卡片上出现内部 ID 重复三遍。

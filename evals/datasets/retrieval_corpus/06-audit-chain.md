# 审计链与哈希

每条审计记录带 prev_hash 与 entry_hash。prev_hash 是上一条已写入记录的
entry_hash，entry_hash 覆盖本条实际写下的字段。校验函数能指出第一个被改过
的行号。

## 篡改可发现而非防篡改

需要说清楚的是：这是篡改可发现，不是防篡改。有磁盘权限的人仍可整条重写，
链只证明哪一行之后被动过。对外措辞必须一致，别再说不可篡改。

## WAL 实例唯一

审计写成链的前提是 WAL 实例必须唯一。若两个进程各写各的链，落到同一个
jsonl 文件里，校验会看到两条交错的链，整天的审计都被判成断裂。所以 WAL
实例必须单点，请求路径与 worker 路径共用它。

## 容量与失败处理

容量按实际写入字节统计，缓冲满溢有计数而不是静默丢最旧。落盘失败不中断
审计，进程内继续接链并计 write_failures。这两个口径的差别曾经让文档替实现
担保过，现在统一由落盘字段决定。

## 审计字段覆盖

审计条目的字段集合只在一个序列化出口维护，WAL 与 ES 都从这里取字段。此前两个
sink 各自手写一份字段清单，于是新加的字段只进了内存对象，落盘时被静默丢弃，
而 README 已声称它们可查。现在每个字段与每个 extra 键都出现在输出里，由测试
强制保证，避免文档再次领先于代码。

# 定位与减法清单（2026-09-22）

一页纸，用于两件事：面试提纲，以及后续开发的过滤器（**不在此清单里的需求默认不做**）。

## 一句话定位

**它是一个 LLM 治理层，不是一个全能 agent。** 价值主张：让不受控的模型输出变得
**可审批（守卫 + 真人 HITL）、可审计（WAL + trace 关联）、可回归（评测门禁）**。

之所以要这么讲：按 12 条 Agent 评测标准自查后，"工程与治理"维度是强通过，
"智能"维度偏弱，而决定体验的恰是后者——于是"看起来全能、用起来智障"。
诚实收敛比继续加功能更有说服力。详见下文自评。

## 保留：继续投入的三条线

| # | 线 | 为什么留 | 现状 |
|---|---|---|---|
| 1 | **飞书治理闭环**（消息 → 路由 → 守卫 → 卡片审批 → 送达 → 审计） | 唯一端到端真人验收过的场景，能现场演示 | 固定公网地址 + 真人点击已验证 |
| 2 | **人工决策回流评测**（HITL 决策 → 数据集 → 人工介入率/放行率） | 把"刹车"变成"标注管道"，是本项目独有的数据资产 | 采集器 + 指标已进评测报告 |
| 3 | **上下文工程**（token 预算 / 裁剪 / 省略摘要） | 直接治长会话退化，是"体验差"的技术根因 | 双引擎共用同一预算策略 |

## 冻结：保留代码、停止扩展

- **双引擎**（FSM + LangGraph）：价值是"用代码回答框架等价性"，面试 30 秒讲完。
  等价性门禁继续跑，但**不再给它添场景**。
- **长期记忆、任务 Agent、Web Chat**：作为"同一编排层的示例应用"存在，
  不追求产品化深度。
- **PR 审查垂直应用**：独立子应用，保持可运行即可。**定位明确为"只读审查"**（2026-09-23）：
  没有 GitHub 写回、没有该链路的 HITL 存储与回调、该链路审计 0 条。它的"需要人工复核"卡片是
  **通知形态**（不带按钮），不再假装可审批。**要变成闭环需要写回接口 + HITL 存储与回调 + 审计
  三件，属独立议题，不在本轮**——也不要再把它当成"待办缺口"反复提起。

## 不做：明确拒绝

- 新渠道（钉钉/企微/Slack…）：接入是配置级工作，讲了就行，不必做。
- 新 provider / 新 dashboard 页面 / 新守卫策略：边际价值为零，只会稀释深度。
- 为演示给模型"打鸡血"（改 prompt 骗过守卫、硬编码输出）：破坏可信度。

## 说法：面试口径

- **模型层主动降级说明**：本机演示用 `moa-qwen`（qwen2.5:1.5b + 小上下文变体），
  因为这台机器只有 4GB 显存；生产建议接强 API——**"换模型不用改闸门"正是这层的卖点**。
- **能力面主动收敛**：被问"支持哪些渠道/框架"，答"渠道是配置级，框架是可选对照，
  我重点做的是把输出关进合规笼子"。
- **边界主动交代**（被追问前先说）：无真实流量（用户量=1）、会话状态与预算累计器
  在进程内（多实例需先接 redis_state）、单机 + 隧道部署。

## 12 条标准自评快照（2026-09-22）

| # | 维度 | 判定 | 关键证据 |
|---|---|---|---|
| 1 | 真实业务问题 | ⚠️ 合格线边缘 | 场景/输入输出明确；无真实用户 |
| 2 | 后端架构 | ✅ 强 | API/编排/工具/网关/存储/鉴权/部署齐全，模块边界有测试钉死 |
| 3 | 数据库与会话持久化 | ✅ | Redis 会话 + 审计 WAL/ES + 向量库 + schema 迁移 |
| 4 | 任务状态管理 | ✅ 含加分 | FSM 8 态**全部真实可达**（2026-09-22 前只有 5 态可达，RETRY/OUTPUT_READY/COMPLETED 是装饰状态）+ HITL 暂停/恢复 + 人工审批节点（真人验收） |
| 5 | 规划/工具/记忆/反思 | ✅ 四项达标（反思是归因型） | 规划/工具/记忆完整；失败归因与恢复已接线——异常带原因重试一次、再失败升级人工（ADR-010）。仍**无 LLM 自我批判式反思**，只有工程层的归因与升级 |
| 6 | 上下文工程 | ✅（本轮补齐） | token 预算 + 裁剪 + 省略摘要，双引擎共用；预算决策进审计 |
| 7 | 可观测性 | ✅ 强 | OTel trace 贯穿 + 审计可关联 + dashboard + 成本/延迟落盘 |
| 8 | 自动化评测 | ✅（含一处诚实标注） | 路由/守卫/E2E + 工具选择（CI 硬门禁，**测的是 MockTaskLLM 规则表**）+ **意图一致性维度（测模型路径，无期望值故设计者不可自证；ADR-011）** + 人工介入率（当前 4 条**全为模拟种子**，报告与摘要已标） |
| 9 | 人机协同 | ✅ 最强项 | 风险分级 + RBAC + HITL 刹车 + **决策回流评测** |
| 10 | 架构决策解释 | ✅ 强 | ADR-002~012 + 已知边界自曝 |
| 11 | 量化收益 | ⚠️ 技术指标齐 | 92% 正则直出、各指标数值、单任务成本；无业务账单 |
| 12 | 真实问题系统 | ✅ 合格线 | 端到端可演示 + 真实约束（4GB 显存/平台契约）+ 真实失败案例 |

**结论**：作为简历项目明显超出合格线；作为生产 Agent，缺口集中在 1/11/12（真实流量），
已用"治理闭环 + 真实工程约束"的叙事替代"用户量大"的虚指。

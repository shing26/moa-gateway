## 一句话定位

**产品：受治理的仓库交付 Agent（`DeliveryRequest -> DeliveryRun`）。**
默认单 Implementer；所有写操作受 bundle、人工审批与合并状态机约束。S0 已实现，真实仓库
端到端验收已完成（2026-10-30，见 `docs/acceptance/2026-10-30-s0-acceptance.md`）；只读
Verifier 是预注册实验 S1，默认关闭。

**支撑层：`app/` 的 LLM 治理运行时；验证层：`bench/` 的等预算多智能体实验台。**
两者用于支撑和检验产品，不表示平台已经承载多个成熟场景。PR 审查与合并通道是现有成熟
负载；Issue 分诊仍处 pilot/受限状态，CI 失败只读诊断已实现但不自动修复。

对外一句话：**"我让 Agent 把仓库变更做完，但推送、CI 与合并都必须留下可复核证据并经过人批准。"**

这里**停用两个词**，并明确交付 Agent 的当前边界（详见 README 顶部 NOTE）：

- **网关**——设计文档 §2.1 判定不成立：请求进来之后是它在干活，不是转发给别人。
- **多智能体系统**——产品层主链路是 5 次**顺序** LLM 调用（`apps/code_review_pipeline`）。
- **交付 Agent**——默认单 Implementer，只读 Verifier 是预注册实验 S1，默认关闭；
  CI 失败诊断是只读辅助入口，不是自动修复或自动合并。

之所以要这么讲：按 12 条 Agent 评测标准自查后，"工程与治理"维度是强通过，"智能"维度偏弱。
诚实收敛比继续加功能更有说服力——**这个项目缺的是删除，不是新功能**。详见下文自评。

## 保留：继续投入的线

| # | 线 | 为什么留 | 现状 |
|---|---|---|---|
| 1 | **飞书治理闭环**（消息 → 路由 → 守卫 → 卡片审批 → 送达 → 审计） | 唯一端到端真人验收过的场景，能现场演示 | 固定公网地址 + 真人点击已验证 |
| 2 | **人工决策回流评测**（HITL 决策 → 数据集 → 人工介入率/放行率） | 把"刹车"变成"标注管道"，是本项目独有的数据资产 | 采集器 + 指标已进评测报告 |
| 3 | **上下文工程**（token 预算 / 裁剪 / 省略摘要） | 直接治长会话退化，是"体验差"的技术根因 | 双引擎共用同一预算策略 |
| 4 | **多 Agent 协作**（R6 多级 supervisor：规划 → handoff → Critic 反思 → 有界修订） | 补上"Agent 之间如何协作"这条能力线；每个 Agent 的输出仍过既有闸门 | 2026-10-09 立项（ADR-022），LangGraph `StateGraph` 实现，治理复用不新写 |
| 5 | **剂量实验台**（`bench/`：L0–L3 等预算对照 + 自报/判决分离 + 防作弊还原） | 这个项目唯一能**证伪**的主张都出自这里 | 第一轮真实曲线已落地（2026-10-19，2 题 × 4 档 × 1 次） |
| 6 | **Issue 分诊（第二任务域）** | 用同一套门禁轨道把实验台方法迁到非编码任务域，验证"方法可迁移"本身 | v3 L0-only 正式批次完成：24/24、0 error、全量对账通过（2026-10-25） |
| 7 | **CI 失败只读诊断**（ADR-032） | 用同一 `DeliveryRequest` 与人工复核边界接入第二个真实负载，不开放修复写侧 | 已实现失败 checks + Actions logs → 本地 JSON/Markdown/request；权限不足时保留部分证据 |
| 8 | **交付 Agent dogfood**（真实变更走 `DeliveryRun` 全链路：goal → 验证 → 推送审批 → CI → 合并审批 → 证据对账） | 把 n=1 真实使用变成独有数据资产（补自评 #1/#11 样本），并为 S1 数据门槛供数（ADR-033） | 2026-10-30 S0 真实验收完成；台账待启动，预注册终点：连续 10 个真实交付或 4 周 |

## 冻结：保留代码、停止扩展

- **双引擎**（FSM + LangGraph）：价值是"用代码回答框架等价性"，面试 30 秒讲完。
  等价性门禁继续跑，但**不再给它添场景**。
- **长期记忆、任务 Agent、Web Chat**：作为"同一编排层的示例应用"存在，
  不追求产品化深度。
- **PR 审查垂直应用**：定位是**经审批的写回 + 合并通道**（2026-10-19 订正——此前本页写
  "只读审查"，与代码不符）：
  - 写回：`apps/code_review_pipeline/review_publisher.py`（`event=COMMENT`，幂等靠
    `posted_review_id`）。
  - 合并：`MergeExecutor` + `MergePoller` + `merge_channel_readiness` 预检，开关
    `CODE_REVIEW_MERGE_ENABLED`（默认关），必须过人工审批门（ADR-021）。
  - 旧口径里"没有 GitHub 写回、没有该链路的 HITL 存储与回调"三件套 **已经过期**，
    不要再引用；仍然成立的是没有真实 PR 流量、合并未达成"连续 10 个 PR"的产品验收——
    关闭路径由 ADR-033 的 dogfood 预注册终点给出，达标与否以台账记录为准。
  - 保持冻结的意思是**不再扩它**，不是"它还是只读的"。

- **R6 多级 supervisor：2026-10-09 单独立项解除冻结**（ADR-022）。解除的是
  "**多 Agent 协作作为一条能力线**"，不是推翻冻结：任务 Agent、长期记忆、
  Web Chat 仍是示例应用，双引擎仍不再添场景。
  协作链路是**新增路径**，不进请求主路径，因此不触碰意图路由与其测试面。

## 不做：明确拒绝

- 新渠道（钉钉/企微/Slack…）：接入是配置级工作，讲了就行，不必做。
- 新 provider / 新 dashboard 页面 / 新守卫策略：边际价值为零，只会稀释深度。
- 为演示给模型"打鸡血"（改 prompt 骗过守卫、硬编码输出）：破坏可信度。
- **收口期间不新增投机模块**：ADR-032 的只读 CI 诊断是已接受的边界例外，仅限
  checks / Actions job logs 的证据采集与本地报告；CI 自动修复、重跑、推送和
  GitHub 写回仍不做。其余文档写了但代码里没有的（MCP、评测 delta 门禁、成本量化、
  多实例化、微模型路由、Rerank 重开/分块升级/换嵌入/租户隔离）一律不做——
  只做"删宣称、改状态"。
- **不再用 qwen2.5:3b + 512 开任何新批次**（含 Issue 分诊多档重试）：v5 B1 已证明
  基线贴地板时增益不可测量，v8 复现同一问题，分诊多档被有效样本门禁拦截——
  三次同类证据足够。换强模型的确认性批次只在真实付费额度到位时另立协议启动，
  在此之前不为其做任何预置开发。

## 说法：面试口径

- **模型层主动降级说明**：本机演示用 `moa-qwen`（qwen2.5:1.5b + 小上下文变体），
  因为这台机器只有 4GB 显存；生产建议接强 API——**"换模型不用改闸门"正是这层的卖点**。
  bench 实验另接中档 API（`nvidia/nemotron-3-super-120b-a12b`，免费端点）。
- **能力面主动收敛**：被问"支持哪些渠道/框架"，答"渠道是配置级，框架是可选对照，
  我重点做的是把输出关进合规笼子"。
- **被问"多智能体到底强不强"**：给曲线，不给结论式宣称——"我这两题上 L1 是峰值，
  L0→L1 +50pp，再往上加是净亏损；但 n=1、只有 2 题，这是方向性证据不是统计结论"。
- **边界主动交代**（被追问前先说）：无真实流量（用户量=1）、会话状态与预算累计器
  在进程内（多实例需先接 redis_state）、单机 + 隧道部署、OTel 只是预留接口。
- **被问"多智能体实验最后测出了什么"**：给授权结论，不给方向性曲线——
  "v5 是唯一授权分析：L3−L0 配对差 0.0、p=1.0、token 7.9–14.8 倍，基线 0% 贴地板，
  所以正确读法是'当前配置下不可测量且高成本'，这就是协作默认关闭的依据。
  要改写它只有一个办法：换强模型让基线脱离地板，重过 pilot 门禁。"

## 12 条标准自评快照（2026-09-22，2026-10-19 订正 #7）

| # | 维度 | 判定 | 关键证据 |
|---|---|---|---|
| 1 | 真实业务问题 | ⚠️ 合格线边缘 | 场景/输入输出明确；无真实用户 |
| 2 | 后端架构 | ✅ 强 | API/编排/工具/存储/鉴权/部署齐全，模块边界有测试钉死 |
| 3 | 数据库与会话持久化 | ✅ | Redis 会话 + 审计 WAL/ES + 向量库 + schema 迁移 |
| 4 | 任务状态管理 | ✅ 含加分 | FSM 8 态**全部真实可达**（2026-09-22 前只有 5 态可达，RETRY/OUTPUT_READY/COMPLETED 是装饰状态）+ HITL 暂停/恢复 + 人工审批节点（真人验收） |
| 5 | 规划/工具/记忆/反思 | ✅ 四项达标（反思是归因型） | 规划/工具/记忆完整；失败归因与恢复已接线——异常带原因重试一次、再失败升级人工（ADR-010）。仍**无 LLM 自我批判式反思**，只有工程层的归因与升级 |
| 6 | 上下文工程 | ✅（2026-09 补齐） | token 预算 + 裁剪 + 省略摘要，双引擎共用；预算决策进审计 |
| 7 | 可观测性 | ⚠️ 达标（一处需澄清） | 审计 WAL 链（tamper-evident）+ dashboard + 成本/延迟落盘是真的；**OTel 只是预留接口**——全仓 2 个 span、未声明 exporter 依赖，设了端点也只落 console。不能说"trace 贯穿" |
| 8 | 自动化评测 | ✅（含一处诚实标注） | 路由/守卫/E2E + 工具选择（CI 硬门禁，**测的是 MockTaskLLM 规则表**）+ **意图一致性维度（测模型路径，无期望值故设计者不可自证；ADR-011）** + 人工介入率（当前 4 条**全为模拟种子**，报告与摘要已标） |
| 9 | 人机协同 | ✅ 最强项 | 风险分级 + RBAC + HITL 刹车 + **决策回流评测** |
| 10 | 架构决策解释 | ✅ 强 | ADR-002~023 + 已知边界自曝 |
| 11 | 量化收益 | ⚠️ 技术指标齐 | 92% 正则直出、各指标数值、单任务成本；无业务账单。bench 曲线量化的是结构收益，不是业务收益 |
| 12 | 真实问题系统 | ✅ 合格线 | 端到端可演示 + 真实约束（4GB 显存/平台契约）+ 真实失败案例 + 剂量实验的负结果 |

**结论**：作为简历项目明显超出合格线；作为生产 Agent，缺口集中在 1/11/12（真实流量），
已用"治理闭环 + 真实工程约束 + 一个能出负结论的实验台"的叙事替代"用户量大"的虚指。

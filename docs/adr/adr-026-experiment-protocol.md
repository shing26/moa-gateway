# ADR-026: 实验协议是机器可读的比较边界

## 背景

ADR-025 固定了 `Experiment → Trial → Run Record`，但没有固定“哪些任务、档位、
模型、预算、重复次数和排除规则算同一批可比较实验”。如果这些条件散落在 CLI 参数、
文档和人的记忆里，同一组命令很容易在不知情时改变口径，旧结果也会被当成新口径的证据。

当前免费端点没有可用的美元成本信号。继续用美元轴会让所有成本停在 0，无法表达
“同等资源下谁更强”；因此首批协议必须明确改用 token 轴，而不是把缺失价格伪装成零成本。

## 决策

1. 首批 8 个任务、L0-L3、provider/model、B1/B3 预算、重复次数、错误重试、排除规则
   与报告边界冻结在机器可读 JSON 中。
2. 协议使用规范化 JSON 计算 `config_hash`。字段顺序不影响哈希，任何语义变化都改变
   协议身份。
3. `任务 × arm` 映射为 Experiment，重复次数映射为该 Experiment 的 Trial；同一批次内
   的单元由 Batch Manifest 编排和恢复，但 Manifest 不替代 Experiment。
4. 免费端点首批使用 `tokens` 主轴：B1 至少 `40 steps / 400000 tokens`，B3 为
   `120 steps / 1200000 tokens`。
5. 只有 `error` 可做有限基础设施重试；`fail` 与 `budget_exhausted` 是实验结果，
   不能靠重试抹掉。重试后仍为 `error` 的记录保留可见，但不进入 pass-rate 分母。
6. 在 formal 阶段每个非缺格达到 3 个有效样本前，只输出方向性观察；协议不授权统计显著声明。

## 替代方案

- **只把口径写进文档**：人可读，但无法阻止参数漂移，也无法给 Experiment 提供稳定身份。
- **每次由 CLI 参数现场拼协议**：灵活，但无法证明两次运行使用同一口径，恢复批次时尤其危险。
- **继续用美元轴**：适合有明确价格的 provider，但不适合当前免费端点；把缺失成本当 0
  会制造虚假的等预算结论。
- **把重复映射为多个 Experiment**：会混淆“实验配置单位”和“同一配置下的重复观察”，
  也让协议级聚合与缺口判断更难保持一致。

## 后果

- 修改任务、arm、模型、预算、重复、重试、排除或报告口径必须提升协议版本，并产生新哈希。
- Batch Manifest 必须引用协议哈希；不能用一个旧 Manifest 恢复成另一份协议。
- 当前协议中的模型参数是首批实验配置，不代表生产默认模型。
- 统计扩展可以新增协议字段和版本，但不能回写或重解释已落盘的旧协议。

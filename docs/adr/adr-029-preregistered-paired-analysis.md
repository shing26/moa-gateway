# ADR-029: 统计声明由预注册配对分析门禁授权

## 背景

M5 和 M6 的 L0-L3 矩阵会积累多次 Trial，但“有 96 条运行”不等于“可以宣称某个
arm 显著更好”。错误、缺口、任务难度和模型/价格不可用都可能让简单总体通过率产生
误导。统计扩展也不能回写 v3 协议或把旧数据重新解释成新口径。

## 决策

1. 新建协议 `multi-agent-first-batch-v4.json`。任务、arm、模型、B1/B3 预算与 v3
   保持一致，但增加独立 `statistics` 字段，因此产生新的 `protocol_hash`。
2. 主要确认性比较在正式实验前固定为 `L3 - L0`，主指标是任务级通过率，分析单位
   是任务，不是把每次 Trial 当成相互独立的任务。
3. 计划样本固定为 8 个配对任务，每个 `任务 × arm` 计划 3 次；至少 3 次有效
   （非 `error`）才可进入主分析。任一任务-arm 有效样本不足即阻止统计声明。
4. 对每个任务分别计算 L3 与 L0 的有效通过率差值，再对 8 个任务做确定性配对
   bootstrap percentile 区间；随机种子和 resample 数写入协议。
5. 同时输出精确符号翻转检验作为诊断。只有置信区间不跨 0 且 `p < alpha` 才授权
   “candidate better/worse”；否则只能报告“不拒绝无差异”。
6. `leave-one-task-out` 和 `origin_stratified` 只作敏感性/描述性分析。E1/E3 子组
   不单独作统计显著声明。
7. 跨模型报告按 `model × arm` 展示，不跨模型合并通过率。模型成本信号缺失时标记
   `unavailable_or_zero` 或 `mixed_or_unpriced`，不得把缺失价格当成 `$0` 优势。
8. 多模型输入必须显式选择单一模型后才能进入主配对分析；不能自动挑“最好模型”再
   宣称显著。

## 后果

- v3 正式批次仍是运行时行为证据；统计确认性结论必须来自 v4 协议和满足门禁的数据。
- 报告中的 `statistical_claims` 由分析结果授权，不再由协议存在或样本数猜测。
- 缺口、错误和样本不足会直接阻止结论，而不是被排除后继续比较。
- 敏感性分析可以帮助判断结论是否依赖单个任务，但不能替代预注册主分析。

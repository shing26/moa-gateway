# ADR-033: S1 设数据门槛——先 dogfood，后实验

日期：2026-10-31
状态：已接受
关联：ADR-026（实验协议）、ADR-029（预注册配对分析）、ADR-030（受治理变更 agent）、ADR-031（受治理仓库交付 agent）

## 背景

S0 已于 2026-10-30 在真实仓库完成端到端验收（`docs/acceptance/2026-10-30-s0-acceptance.md`）。
下一步存在分叉：按 ADR-031 的预注册继续实现 S1 Verifier 实验（实现计划已写，55 项任务
未动工），还是先把交付 Agent 投入真实使用（dogfood）。

v5 的授权结论留下过一次教训：基线贴地板时，实验增益不可测量。S1 测量"只读复核体能否
减少假通过"，其前提是实现体在真实任务上存在非退化的通过率，且能观察到假通过的真实
样本——这个数据目前不存在。现在实现 S1，预注册的配对比较没有基线可配，大概率重演 v5：
n 小、差值 0、结论只能是"不可测量"。同时，自评缺口 1/11/12（真实流量、业务收益、真实
问题系统）不因 S1 而改变——dogfood 直接补这组样本，S1 不补。

## 决策

1. **先 dogfood。** 真实变更走 `delivery run` 全链路（goal → 实现 → 验证 → 推送审批 →
   PR → CI → 合并审批 → 证据对账），凡能走此链路的变更不再手工开 PR。**真实交付的定义**
   预注册如下：goal 来自真实需求（非验收造数）；变更对象是真实维护的仓库；验证命令是
   该仓库的真实门禁，不是为验收写的一次性断言。
2. **终点预注册。** 连续 10 个真实交付完成全链路，或自启动起 4 周内凑不满——两个结局
   都如实记录进台账。台账是一份文档，不是新模块；dogfood 期间不新增产品代码。
3. **S1 数据门槛。** S1 实验仅在以下条件同时满足时启动：(a) 台账显示实现体真实任务
   通过率非退化（约 20%–80%）；(b) 观察到 ≥3 次假通过候选；(c) S1 任务集从真实
   dogfood 任务取材，不现编 toy 任务。
4. **不达标即降级。** 门槛不满足时，S1 以"设计完成、当前数据下不可测量"的负结论归档，
   不强行开跑；该负结论本身可进入对外叙事。ADR-031 中 S1 的预注册地位由本条承接，
   预注册纪律（ADR-029）不破坏。
5. **治理不变。** dogfood 的每一次交付仍走既有 bundle、审批、审计与合并状态机；
   本决策不放松任何治理约束，也不改变默认 dry-run 与显式开关。

## 替代方案

- **立即实现 S1**：无法回答"任务集上假通过率是多少"这一预注册前置问题，重演 v5 的
  概率高。否决。
- **完全冻结不再投入**：同时放弃作品集深度与真实使用两条收益，且"连续 10 个 PR"的
  产品验收永无关闭路径。否决。
- **dogfood 与 S1 并行**：S1 的实现工作量（数十文件、新 bench harness）会吃掉 dogfood
  需要的同一份时间，且任务集仍无真实来源。否决。

## 后果

- 实现体的能力天花板（单 Implementer、四工具、固定验证命令、不支持多轮交互）从假设
  变成被测量的对象；天花板高度直接决定 S1 门槛是否通过。
- 自评 #1 从"无真实用户"变为"n=1 真实使用（dogfood 进行中）"；#11/#12 获得真实样本，
  但仍是单用户，不得夸大为流量验证。
- "合并未达成'连续 10 个 PR'的产品验收"获得明确的关闭路径；达标与否以台账为准。
- 门槛通过时，S1 的基线与任务集已有来源；不通过时，S1 以负结论关闭，实验台"只跑
  能测量的实验"的可信度反而增强。

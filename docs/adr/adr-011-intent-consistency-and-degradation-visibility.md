# ADR-0011: 意图一致性维度、路由降级可见性与模拟数据标记

日期：2026-09-22
状态：已实施
关联：ADR-010（生命周期与重试）；`evals/datasets/hitl_feedback.jsonl`；外部六维能力评估（2026-09-22）

## 背景

外部评估用真实反流数据指出一处此前未被发现的问题：`hitl_feedback.jsonl` 里**同一句输入**
的意图判定在 `assistant` / `translate` 之间摆动（4 条里两种各两条），并据此推断"真实一致率
约 54%"。这个观察是对的，且它戳中了评测体系的根本局限——`intent.jsonl`（50 条）恒 1.0，
但数据集、正则表、标签出自同一设计者，只能证明"实现符合我的预期"。

当时的推断（"意图判定不稳定，一致率 54%"）**不成立**：n=4 推不出 54%（评估文档自己在别处
也写了 n=4 无统计意义），而且成因不是模型摇摆。真正需要的是**一个能测模型路径、且设计者
无法自证的维度**。

## 决策

1. **新增 `intent_consistency` 维度**（`evals/datasets/intent_consistency.jsonl`，11 条 × 5 次重放）。
   与 `run_intent_eval` 的根本区别是**没有 `expected_intent`**：只看同一输入多次判定是否收敛。
   设计者写不出 1.0——除非系统真的稳定。
2. **用例必须绕开正则表**。纯正则层是确定性的，拿它测一致性必然 1.0。由
   `test_intent_consistency_cases_bypass_the_regex_table` 逐条断言"不命中任何意图正则"来守住。
3. **不设数值门禁**。在拿到真实数值之前定阈值就是编数字，而"编数字"正是这个维度要治的病。
   门禁落在**测量本身的正确性**上（摆动/稳定/降级三种情形都有单测），不落在数值上。
4. **离线标 `skipped`，不给假的 1.0**。没有模型就没有可测的兜底路径；报一个漂亮的 1.0
   比不测更糟，因为会让人以为模型路径也稳。
5. **夹具不预热模型**。冷启动降级是**被测系统真实行为**，夹具替它"修好"属于同一类错误
   （对照：`--offline` 报成功）。改为把 `levels` / `degraded_calls` / `note` 打进报告与
   命令行摘要，让数字自己说明它是否可信。
6. **审计新增 `route_fallback`**（路由层级）。此前审计只记 `intent` 不记层级，于是"路由
   一直在超时降级"在数据里完全看不见——这正是上面那句输入摆动的真实成因。
7. **HITL 模拟数据必须被标出**。`load_hitl_feedback` 从 `session_id` 前缀派生
   `synthetic_cases` / `real_cases`（口径与 `collect_hitl_feedback.py` 一致，不改数据集
   schema），摘要对全模拟数据打 `(全为模拟)`。数字保留但限定词必须同行。

## 后果

- **实测（2026-09-22，本机 moa-qwen + 4GB 显存）**：

  | 条件 | 路由层级分布 | stable_rate |
  |---|---|---|
  | 不预热（冷启动） | `none` × 55（全部降级） | 1.0 —— **"一致地降级"，无意义** |
  | 单独预热后 | `router_llm` × 55 | 1.0（真实一致） |
  | 完整活体跑（含冷启动） | `router_llm` 53 / `none` 2 | 0.9091（10/11），报告自带警示语 |

- **根因（已验证）**：`ROUTER_LLM_TIMEOUT_MS=2000` 而本地小模型冷启动首次 `classify` 实测
  4.2~4.5s；`asyncio.wait_for` 超时会取消请求，模型因此热不起来，后续每次调用都超时 →
  **所有非正则输入静默降级成默认意图 `assistant`**。
- **对那句摆动的最终解释**：`ic-001`（就是 `hitl_feedback` 里那条输入）5 次重放得到
  `{assistant: 2, translate: 3}`，而报告同时记录的 `degraded_calls` **恰好是 2**——
  两个 `assistant` 就是两次超时降级（默认值），三个 `translate` 才是模型判断。
  **不是判定不稳定，是"真判断"与"静默降级"之间的超时竞态。**观察成立，原诊断不成立。
- **未修（留给部署决定）**：超时值本身是部署相关的（本地小模型该上调，接强 API 时 2000ms
  的快速失败更好），所以只改 `.env.template` 注释与 README 已知边界，不改代码默认值；
  启动预热是可选优化，未做。
- `intent` 维度的 docstring 与 README 已把"只测正则表"写明；README 评测表加了"测的到底是什么"
  一列，把 `tool_selection`（测的是 `MockTaskLLM` 的规则表）与 HITL（全为模拟）如实标注。

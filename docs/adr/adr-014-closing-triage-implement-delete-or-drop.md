# ADR-0014: 收尾——把剩余台账逐项落到"实现 / 删除 / 明确不做"

日期：2026-09-23
状态：已实施
关联：ADR-010（生命周期与刹车）、ADR-011（一致性维度）、ADR-012（配置单一来源）、ADR-013（回调可信度）

## 背景

项目进入收尾，要求**不留待办**：每一项要么实现、要么删除、要么明确不做并写明理由。
清单来自 2026-09-23 的两次盘点（"还有什么台账和债" + triage 三分类）。

## 决策

1. **删除 `app/redis_state/{lock,stack}.py`**（实现/删除 → 选删除）。
   `IdempotencyLock` / `LuaLockFactory` / 状态栈从未接入请求路径，只有单测在驱动它们；
   而 HITL 的幂等已改用挂起记录自身的**原子认领**（`pop_hitl`），它们更没有存在理由。
   保留"没人用的抽象 + 配套测试"是"看起来有能力"的死代码——与 `Event.FALLBACK_APPLIED`、
   `RuleEvaluator.MAX_RETRY` 同类，一并清掉。三个 Lua 脚本常量搬到唯一使用者
   `memory_fallback.py`（`MemoryStateStore.eval` 是活的，测试改成直接用脚本常量驱动，
   覆盖面不变）；`store.py` 是活的（`/healthz` 用），保留。
   多实例会话状态真要外部化时，**按当时的真实需求重新设计**，而不是复活一段从未被真实场景
   检验过的代码。

2. **审批单据补两个字段，并明确拒绝另外三个**。`HitlRequest.applicant`（谁申请的，
   取自事件 user_id / 飞书 sender open_id）与 `HitlRequest.reason`（为什么：命中原因或
   失败原因），并渲染到飞书卡片上。**刻意不加 `resource` / 权限 / 期限**：那三样是
   "操作审批"（IT 权限、生产变更）的字段，本项目的治理对象是**模型输出**，加上它们会把
   定位推向操作审批、与 `delivery/定位与减法清单.md` 冲突。定位若变，应连同单据模型一起重设。

3. **审批人白名单 `HITL_APPROVER_IDS`**（实现）。逗号分隔的 open_id，**非空即强制**：
   名单外的点击 → 403/拒绝；**校验在认领之前**，否则一个没有权限的人点一下就把待审批记录
   消耗掉了，别人再也批不了。取不到点击者（平台未带 operator）而白名单非空时同样拒绝——
   验不了就不放行。留空 = 不校验（保持既有行为），但此时"同一会话里任何人点一下都能批准"，
   所以 `.env.template` 与 README 都写明。
   **这条的顺序 bug 是被测试逼出来的**：我最初把校验插在 `pop_hitl` 之后，
   `test_webhook_callback_refuses_operator_outside_allowlist` 当场断言"记录不该被消耗"而红。

4. **加密模式明确不做，并删掉形同虚设的配置字段**。它需要 AES 解密加密体 +
   `X-Lark-Signature` 的 HMAC/时间戳校验，而这两件**无法对着真实加密回调验证**——
   与其发布一段无法确证正确性的加密路径，不如明确不支持。原先的 `FEISHU_ENCRYPT_KEY`
   字段从未被任何代码使用（配了它只会让加密事件被静默 ignored），已删除；现在收到
   `{"encrypt": ...}` 一律返回 `400 encrypted_events_unsupported` 并在日志里说明原因
   （此前是静默丢弃，配了加密却收不到任何事件也无从察觉）。

5. **一致性数据集扩样 11 → 20 条**（实现）。新增的是**多样化的非正则输入**，而不是规划里
   写的"24 条报价类"——那个数字来自"一致率 54%"的错误前提（真因是路由超时竞态，见 ADR-011）；
   稳定性维度的样本应该多样，只留 3 条报价类变体（历史那次摆动正出在报价语境）。
   新用例全部通过"不命中任何意图正则"的漂移守卫。

6. **路由正则补 `写一个|写个|编写`**（实现，有测量依据）。此前"写一个单例模式示例"
   "写一个爬虫示例"这类**最典型的编码请求完全不命中 coding**，会落到模型兜底甚至默认意图。
   候选正则做了对照测量（正则层、确定性）：e2e 标签命中 23/30 → **29/30**，
   而 intent 数据集准确率保持 1.00、一致性数据集"必须不命中"约束仍 0 违反。
   选这三个而非裸 `写`：裸 `写`会把"写一份周报"也吞成 coding（测试里留了反例）。

7. **工具全失败 → 接上已有的刹车**（实现）。判定 `tool_calls > 0 and tool_errors == tool_calls`
   （**全部**失败，不是"有失败"）时补一条 eval issue `all_tool_calls_failed`，
   经 `_verdict_from_eval_issues` → REVIEW → 人工。不新增机制、不改重试语义（ADR-010 的
   "工具级失败由 ReAct 自愈"仍然成立）；部分失败不刹车——那正是模型该自己收敛的情形。

## 后果

- 测试 **778 → 780 passed / 0 skipped**（删掉 8 条只测已删模块的用例、新增 12 条覆盖本轮行为）；
  `ruff`、`bandit -r app` 干净；红队门禁 exit 0；`eval --offline` 退出码 0。
- **仍未做、且明确不做**：加密模式（上面第 4 条）、回调的 RBAC 角色校验（白名单只回答
  "这个人能不能批"，不回答"他是什么角色"——角色仍来自 `MOA_DEFAULT_ROLE`）、
  路由的模型层分类质量（`intent_match` 的残余失配一半是数据集标签本身的问题，
  且标签里 `assistant` 是哨兵不是真值——要对齐得先重写标签，属独立议题）。
- **一个可复用的模式**：本轮好几处是"**测试先红，实现才改对**"（白名单顺序、`applicant`
  测试用错了桩 guard）。这与先前几轮的教训一致：**先写断言、再让实现去满足它**，
  比写完实现再补测试更容易暴露真问题。

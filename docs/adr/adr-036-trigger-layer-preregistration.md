# ADR-036: 自动触发层预注册——现在不做，做时必守四个契约

日期：2026-11-07
状态：预注册（未实施）
关联：ADR-031（交付 Agent 主链路）、ADR-032（CI 失败只读 triage）、
ADR-033（dogfood 台账）、`docs/competitive-analysis.md`

## 背景

当前交付链的入口是**人发起**的 `DeliveryRequest`；ADR-032 的只读 CI triage
是离自动化最近的一步，但仍是"人看完报告再决定"。问题迟早会来：能不能让
"仓库里发生了某事"（issue 新建、CI 转红、PR 更新）**自动**发起一次交付或
triage？

外部参照（详见 `docs/competitive-analysis.md`）显示这一层已经有成熟的失败
教训与行业惯例：全量轮询等于默许 agent 处理任何人的请求；幂等标记放本地
状态文件会在换机后重复处理；无限流的连续唤醒会烧钱又刷屏。

## 决策

**现在不做自动触发层**。理由：主链路的验收标准是"人发起、人批准、可复核"，
触发层会同时动"谁发起"这个尚未被实验过的假设（S1 未开）；在 dogfood 台账
（ADR-033）收尾前不引入新的变量。

**但四个契约束缚已预注册**——将来实现时必须逐条满足，不是"到时候再说"：

1. **触发要有许可语义**：只有满足显式条件的活动才算授权（指派给我 / label
   白名单 / 特定 check 转红），默认跳过 bot 与草稿。全量轮询是反模式。
2. **幂等标记留在外部系统**：处理完成必须在远端留标记（issue/PR 上的固定
   格式标签），本地状态文件只许做缓存。换机器、换会话、重装后不得重复处理。
3. **限流与退避是标配**：单次唤醒批量上限、每小时唤醒上限、失败指数退避
   （封顶 30 分钟，成功即复位）。401 时每 30 秒打一次 API 的定速重试是事故。
4. **observe 模式先于自动模式**：触发判定照常跑，但只记录"本轮本会触发
   哪几条"而不执行。观察期数据先行，再开自动。

**升级触发点**（满足其一才立项，不凭感觉）：

- ADR-032 的只读 triage 开始稳定产出被人采信的报告，且"等人工发起"成为
  实际的瓶颈环节；
- dogfood 台账收尾后，S1 实验需要"事件驱动"的对照臂。

## 后果

- 正面：边界写在前面——将来实现时这四个契约是**判收标准**而不是灵感来源；
  也为面试叙事提供"调研后主动画界"的实证。
- 负面：短期内交付仍依赖人发起，自动化程度低于同类产品；接受——产品的
  差异化在治理深度，不在触发速度。

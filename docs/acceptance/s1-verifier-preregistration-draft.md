# S1 只读 Verifier 预注册（草案，待批准）

状态：**草案**——这是预注册文本，不是实验开工令。批准后进入 `待启动`，实际开跑
仍受 ADR-033 第 3 条的三项数据门槛约束。

关联：ADR-029（预注册纪律）、ADR-031（S1 的定义）、ADR-033（S1 数据门槛）

## 假设（预注册，不可事后改写）

H1：在真实 dogfood 交付的 bundle 上，一个只读 Verifier（可读文件、可搜索、可跑
固定验证命令；不可写、不可审批、不可合并，ADR-031 决策 4）能把**人审才发现**的
缺陷比例降低。

H2：该收益不以显著更多的 revise 轮次为代价——Verifier 的假拦截（把合格 bundle
打回）不超过被它真实拦下的缺陷数。

## 主指标与分析单位

- **主指标：人审前缺陷拦截率。** 定义为：Verifier 在推送审批前标记 `revise` 且
  人审确认确属缺陷的 bundle 数 ÷ 人审确认存在缺陷的 bundle 总数。
- **副指标：假拦截率** = Verifier 标记 `revise` 但人审判合格的 bundle 数 ÷
  Verifier 标记 `revise` 的总数。H2 要求假拦截率 < 50%。
- 分析单位是**交付（delivery）**，不是工具步。一次交付的多个 verdict 取最后一次。
- 参照组：台账中"人审才发现"的历史交付（第 5 行的 README 改坏、第 3 行的误挡）。

## 判定门槛（预注册）

- 拦截率 ≥ 60%（6 成以上本该人审才能发现的缺陷在推送前被拦）且假拦截率 < 50%，
  才可宣称"Verifier 减少假通过"；否则只能报告"未达门槛"。
- 样本 < 8 次含缺陷的交付时，任何方向性结论都不授权——直接引用 ADR-033 的负
  结论格式归档。

## 数据门槛（照抄 ADR-033 第 3 条，开跑前置）

(a) 台账显示实现体真实任务通过率非退化（约 20%–80%）；(b) 观察到 ≥3 次假通过
候选；(c) S1 任务集从真实 dogfood 任务取材。

**当前读数**（2026-11-05，第 6 行落地后）：通过率 4/17 次运行 ≈ 24%（按运行计；
按 goal 计 4/6 ≈ 67%）——门槛 (a) 按哪个口径算，**需要在批准本预注册时定死**，
本草案建议按 goal 口径。假通过候选：1 次（第 5 行 README 改坏），不足 3 次，
门槛 (b) 未满足。**因此 S1 现在不能开跑；本文档只锁定设计。**

## 实现边界（批准前不写产品代码）

- 拓扑开关 `DELIVERY_TOPOLOGY=verified` 已在 flow 层留位（当前显式拒绝）。
- Verifier 的工具集是现有 `build_toolset` 的只读子集：`read_file` / `search` /
  `run_tests` / `git_diff`，去掉一切写与 GitHub 访问。工具策略层已有此口径
  （ADR-031 决策 4），S1 只是第一次把它接进交付流。
- 预算：Verifier 单独计 `DELIVERY_MAX_STEPS` 的一个份额（批准时定值，建议 12 步）。
- 判定写进 `VerifierVerdict`（模型已有）；`revise` 的交付回到 Implementer，
  轮次上限 1 次（批准时定值）。

## 终止与归档

- 数据门槛 4 周内不满足（与 dogfood 窗口 2026-11-28 同期）：按 ADR-033 第 4 条
  以"设计完成、当前数据下不可测量"归档，本预注册文本即为设计完成的证据。
- 实验开跑后，指标、门槛、样本口径不得修改；修改即实验作废重注册。
